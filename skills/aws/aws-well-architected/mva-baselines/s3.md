# S3 — MVA Baseline

## Overview

Amazon Simple Storage Service (S3) provides object storage for data of any size.

**MNA (Minimum Needed Architecture):** A bucket with a globally unique name.
**MVA (Minimum Viable Architecture):** Public access blocked, encryption enabled, versioning, logging, lifecycle policies, governance tagging, and appropriate access controls.

---

## Common (All Environments)

Items required regardless of environment tier.

| Pillar | MVA Item | Severity | Why |
|--------|----------|----------|-----|
| Security | Block all public access (BlockPublicAcls, IgnorePublicAcls, BlockPublicPolicy, RestrictPublicBuckets) | Critical | Public buckets are the most common S3 security incident |
| Security | Default encryption enabled (SSE-S3 minimum) | High | Unencrypted data at rest is a compliance violation |
| Security | Bucket policy restricts access (no wildcard principals) | High | Overly permissive policies expose data |
| Operational Excellence | Governance tags applied (7 core tags) | High | Untagged resources violate governance compliance |

## Development

Additional items beyond Common for development environments.

| Pillar | MVA Item | Severity | Why |
|--------|----------|----------|-----|
| Security | HTTPS-only access enforced via bucket policy (`aws:SecureTransport`) | Medium | Prevents unencrypted data in transit |
| Reliability | Versioning enabled | Medium | Enables recovery from accidental deletions/overwrites |
| Cost Optimization | Lifecycle policy configured (transition or expiration for non-essential data) | Low | Prevents unbounded storage cost growth |

---

## Staging

Additional items beyond Development for staging environments. Critical/high gaps BLOCK execution when enforcement is `strict`.

| Pillar | MVA Item | Severity | Why |
|--------|----------|----------|-----|
| Security | Access logging enabled (to separate logging bucket) | High | Staging should validate logging before production |
| Security | Encryption upgraded to SSE-KMS for sensitive data | Medium | KMS provides key management and audit trail |
| Reliability | Versioning enabled | High | Required for staging (elevated from Medium in dev) |
| Reliability | Object lock or MFA delete for critical data | Medium | Prevents unauthorized deletion of important data |
| Operational Excellence | Bucket inventory configured | Medium | Tracks object metadata for compliance and management |

---

## Production

Additional items beyond Staging for production environments. ALL items are mandatory — no override path.

| Pillar | MVA Item | Severity | Why |
|--------|----------|----------|-----|
| Security | Encryption with SSE-KMS (customer-managed key for regulated data) | High | Full key management control for production data |
| Security | VPC endpoint for S3 access (no public internet path) | Medium | Data should not traverse the public internet |
| Reliability | Cross-region replication for disaster recovery | High | Production data must survive regional outages |
| Reliability | MFA delete enabled for versioned buckets with critical data | High | Prevents even privileged users from accidentally deleting data |
| Cost Optimization | Intelligent-Tiering or lifecycle policies for cost optimization | Medium | Production data grows; automatic tiering controls cost |
| Cost Optimization | S3 Storage Lens or metrics configured | Low | Visibility into storage patterns for cost management |
| Operational Excellence | CloudWatch alarms for error rates and request metrics | High | Production must have monitoring and alerting |
| Operational Excellence | Deployed via IaC (CDK/Terraform/CloudFormation), not direct CLI | High | Production infrastructure must be reproducible |

## Gap Detection Guide

### Block All Public Access

- **Check command:** `aws s3api get-public-access-block --bucket {bucket_name}`
- **Gap condition:** Any of the four settings is `false` (BlockPublicAcls, IgnorePublicAcls, BlockPublicPolicy, RestrictPublicBuckets)
- **Severity:** Critical
- **Remediation:** `aws s3api put-public-access-block --bucket {bucket_name} --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true`
- **Remediation description:** Blocks all public access paths to the bucket

### Default Encryption

- **Check command:** `aws s3api get-bucket-encryption --bucket {bucket_name}`
- **Gap condition:** Returns `ServerSideEncryptionConfigurationNotFoundError` or uses AES256 when KMS is required
- **Severity:** High
- **Remediation:** `aws s3api put-bucket-encryption --bucket {bucket_name} --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"aws:kms"}}]}'`
- **Remediation description:** Enables default server-side encryption for all new objects

### Versioning

- **Check command:** `aws s3api get-bucket-versioning --bucket {bucket_name}`
- **Gap condition:** `Status` is not `Enabled`
- **Severity:** Medium (dev), High (staging/prod)
- **Remediation:** `aws s3api put-bucket-versioning --bucket {bucket_name} --versioning-configuration Status=Enabled`
- **Remediation description:** Enables versioning to recover from accidental deletions

### Access Logging

- **Check command:** `aws s3api get-bucket-logging --bucket {bucket_name}`
- **Gap condition:** `LoggingEnabled` is null or empty
- **Severity:** High (staging/prod)
- **Remediation:** `aws s3api put-bucket-logging --bucket {bucket_name} --bucket-logging-status '{"LoggingEnabled":{"TargetBucket":"{log-bucket}","TargetPrefix":"s3-access-logs/{bucket_name}/"}}'`
- **Remediation description:** Enables access logging for audit and security

### HTTPS-Only Access

- **Check command:** `aws s3api get-bucket-policy --bucket {bucket_name}`
- **Gap condition:** No policy statement with `Condition: {"Bool": {"aws:SecureTransport": "false"}}` and `Effect: Deny`
- **Severity:** Medium
- **Remediation:** Add bucket policy statement denying access when `aws:SecureTransport` is false
- **Remediation description:** Prevents unencrypted (HTTP) access to bucket contents

### Lifecycle Policy

- **Check command:** `aws s3api get-bucket-lifecycle-configuration --bucket {bucket_name}`
- **Gap condition:** Returns `NoSuchLifecycleConfiguration`
- **Severity:** Low (dev), Medium (prod)
- **Remediation:** `aws s3api put-bucket-lifecycle-configuration --bucket {bucket_name} --lifecycle-configuration file://lifecycle.json`
- **Remediation description:** Automates transitions to cheaper storage classes and expiration of old data

### Governance Tags

- **Check command:** `aws s3api get-bucket-tagging --bucket {bucket_name}`
- **Gap condition:** Any of the 7 core tags missing (Name, Environment, Owner, CostCenter, Application, CreatedBy, CreatedDate)
- **Severity:** High
- **Remediation:** `aws s3api put-bucket-tagging --bucket {bucket_name} --tagging 'TagSet=[{Key=...,Value=...},...]'`
- **Remediation description:** Applies required governance tags for compliance

### Cross-Region Replication

- **Check command:** `aws s3api get-bucket-replication --bucket {bucket_name}`
- **Gap condition:** Returns `ReplicationConfigurationNotFoundError`
- **Severity:** High (production only)
- **Remediation:** Configure replication with `aws s3api put-bucket-replication`
- **Remediation description:** Replicates objects to a different region for disaster recovery

### CloudWatch Alarms

- **Check command:** `aws cloudwatch describe-alarms --alarm-name-prefix {bucket-name}`
- **Gap condition:** No alarms exist for 4xxErrors, 5xxErrors, or BucketSizeBytes
- **Severity:** High (production only)
- **Remediation:** Create CloudWatch alarms using S3 request metrics
- **Remediation description:** Alerts on elevated error rates and unexpected storage changes

## Notes

- Production MVA is the superset — all lower tiers are subsets
- Higher layers (org/BU) can ADD items but cannot remove core items
- Only the user can accept gaps below core MVA (non-production only)
- S3 public access block should be enabled at the account level as well as bucket level
